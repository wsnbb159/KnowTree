# 知树 KnowTree · AI 协作过程纪要

> 本文件是「LearnBuddy 对话记录」交付材料的整理版。记录了队长与 AI 搭档（阿树 / Ashu）在 LearnBuddy 平台上协作完成本作品的关键决策、返工与踩坑，按时间倒序整理。原文对话保留在 LearnBuddy 会话中，此处摘其要，便于评委核对「AI 工具使用」评分项。

## 协作模式

- **角色**：队长（第一责任人，决策）+ AI 搭档（技术执行与判断）。队长不接受被架空成观众，每个关键决策都由队长拍板。
- **工作流**：对话式推进。AI 先读代码 / 跑脚本 / 查资料，再带方案回来；不是把选择题甩给队长。
- **硬约束**：9/24 必须上线，9/25 只做视频与 PPT，9/26 只做兜底提交。

## 关键决策与返工（倒序）

### 2026-09-24 · 免费模型服务商接入

- **诉求**：把免费版的豆包、DeepSeek、WorkBuddy 配进知树。
- **AI 判断**：
  - WorkBuddy 没有对外开放的模型 API —— 它是智能体平台本身。知树已以「专家包」形态跑在 WorkBuddy 里，这本身就是 WorkBuddy 形态。网页端用同族「腾讯混元 Lite」（官方永久免费）顶替「腾讯系免费」选项，并如实标注。
  - DeepSeek 官方 API 无免费档；免费 DeepSeek 走火山方舟（每模型 50 万 tokens 免费）或硅基流动免费蒸馏模型。
  - 豆包走火山方舟 OpenAI 兼容端点，新用户每模型 50 万 tokens，且有视觉模型，能撑住拍题链路。
- **落地**：`PROVIDER_PRESETS` 升级为富元数据（免费档位 / 识图能力 / 密钥申请直链），设置页从一行预设按钮变成服务商卡片；密钥按 baseUrl 记忆，切换不丢；非视觉模型提前拦截拍题。
- **验证**：tsc 零错误、两个 verify 脚本通过、vite build 成功（570 KB 主包）、浏览器实测 7 张卡片渲染、Doubao 自动填充 + DeepSeek 视觉警告触发。

### 2026-09-20 · 交付材料与双形态确立

- **决策**：不做正式环境部署（CloudBase 迁移取消），改「智能体形式」，唯一硬要求 = 可交互体验。
- **双形态**：网页版（已上线）+ LearnBuddy 专家包。专家包里把归因算法用 Python 等价实现打包进去（`diagnose.py`），而非只给提示词 —— 否则专家会退化成普通聊天机器人，丢掉最核心的确定性归因能力。两版结论实测完全一致。
- **PPT 生成**：本机 SlideP 服务与 CLI 版本不匹配（`/localapi/keyframe` 404）→ 改用 python-pptx 自写生成器。pip 必须用官方源 + trusted-host（清华镜像报 "from versions: none"）。Windows 中文文件名触发 safe-delete 异常 → 产物用英文名 `deck.pptx`，交付时再重命名。
- **GitHub**：本机推送报 `CRYPT_E_NO_REVOCATION_CHECK` → 诊断（gitee 200、github 000、关 sslVerify 可过）→ 本地配 `http.sslBackend openssl` + `http.sslVerify false`（已向队长说明安全取舍）+ `http.postBuffer 524288000`；408/502 重试后成功，8 次分层提交。

### 2026-09-19 · 高数补全与口径订正

- **补全**：高数从 32 → 49 节点 / 9 章 / 84 边。新增微分方程、三重积分、无穷级数；补上跨模块依赖 `定积分换元 → 极坐标 → 柱面坐标 → 球面坐标`（跨第 5 章到第 10 章 4 跳）。
- **章节号对齐教材**：自编章节号与同济第七版真实编号不符，会把「第10章」排到「第1章」前面。全部改回教材真实编号，排序统一 `localeCompare(x, 'zh-Hans-CN', { numeric: true })`。
- **口径订正（重要返工）**：9/19 把 `blastRadius=9` 理解成「含源头自身」，据此禁用了 9 这个数字。9/20 核实发现理解有误，作废重来 —— `blastRadius=N` 是下游知识点总数（不含自身），聚类「连带 M」是其中已失效的，关系是 `M ≤ N`。讲「已经拖垮多少」用 M（可列名字，更有力）；讲「补它能救回多少」用 N。界面文案统一为「下游 N 个知识点会跟着受益」。
- **归因落点规则踩坑**：`locateGap` 选「通往考点的路径上、最靠近考点的失效边界」。写演示讲解时若预先认定链条（例如认定会回溯到换元法），会出现「横幅说卡在 A、正文说 A 你是清楚的」这种自相矛盾。修复：写文案前先用验证脚本跑出真实落点。
- **多课程串味（严重 Bug）**：演示画像 / 案例硬编码 → 切课时数据串味、归因给出荒唐结论且不报错。修为 `demoCasesFor(courseId)` / `demoMasteryFor(courseId)` 分发。

### 2026-09-19 之前 · 架构与差异化

- **北极星**：拍题 → 不给答案，给诊断。沿前置依赖链回溯 + 错因分类（概念缺失 / 前置断层 / 方法误用）。技术护城河在「卡点归因」。
- **分层**：领域层不依赖 UI，可独立验证（`scripts/verify-domain.ts` 带 assertions，退出码非零即失败）。改知识树后必须复跑。
- **双模式**：环境无模型密钥 → 必须做演示模式（内置样例）+ 远程模式（OpenAI 兼容）。防「评委点开发现不能用」。
- **教师端**：班级卡点热力图是本作品落在「教学管理」方向而非纯学生工具的关键，不能砍。
