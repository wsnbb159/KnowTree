# 知树 KnowTree

> 拍下不会的题，知树不只给答案，而是把它挂到课程知识树上，告诉用户卡在哪个知识点、为什么卡、接下来补什么。

面向「AI + 教学管理助手」场景的多模态教学智能体。纯前端静态应用，无后端。

---

## 它和普通拍题工具的区别

市面上的拍题工具回答的是「这题怎么做」。知树回答的是另外三个问题：

| | 普通拍题 App | 知树 KnowTree |
|---|---|---|
| 输出 | 这道题的解答 | 卡点定位 + 成因 + 补救路径 |
| 视角 | 单题 | 整门课程的知识结构 |
| 归因 | 无（模型自由发挥） | 图算法沿前置依赖链回溯，可核对 |
| 答案给法 | 直接给 | 分三级解锁，防止学生只看答案 |
| 给老师 | 无 | 班级卡点源头收敛，决定「下节课讲什么」 |

同样的失守图景下，普通工具告诉你「你有 13 个知识点不会」，知树告诉你「底层其实只有 4 个洞，先补最大的那 1 个，能连带解开下游 8 个知识点」。

## 核心链路

```
拍题 → 题目理解 → 知识点定位 → 卡点归因 → 补救路径 → 变式复测
       (模型)      (模型+召回)   (图算法)     (模型)     (自评回写)
```

链路共五步，其中 **第 4 步「卡点归因」由确定性图算法完成，模型无权推翻** —— 这是本项目的技术主张：让模型做它擅长的事（读懂图、讲明白），让算法做它擅长的事（可验证的因果推断）。

### 归因引擎怎么工作

给定一份掌握度画像和一道题目：

1. **定位考点**：从题目解析出直接考查的知识点（如「树问题的递归分解」）。
2. **前置闭包回溯**：沿知识树的前置依赖边向上游搜索，找到最早断裂的那个节点。
3. **区分两类断层**（关键设计）：
   - `prerequisite` —— 前置已经断了，问题在上游；
   - `self` —— 前置都健康，问题就在考点自身（属于"方法误用"或"概念缺失"）。
   
   如果不做这个区分，所有错误都会被判成「概念缺失」，归因退化成废话。
4. **失效边界计算**：算出这个断层波及的下游知识点数量（`blastRadius`）。
5. **根源收敛聚类**：把全树的断层聚类到少数几个源头，按收益排序。

在内置演示画像下，`node scripts/verify-domain.ts` 的实测输出：

> 全树 13 个断层 → 收敛为 **4 个源头**。
>
> 最大源头「函数调用栈与递归展开」（当前 38 分）连带拖垮下游 **8 个知识点**：
> 二叉树遍历、层序遍历、线索二叉树、树问题的递归分解、二叉排序树、
> 平衡二叉树 AVL、深度优先遍历 DFS、拓扑排序与关键路径。
>
> 因果链实例：函数调用栈 → 二叉树遍历 → 二叉排序树 → 平衡二叉树 AVL。

在《高等数学》上，同一套算法跑出的是另一种形态：断层更分散（16 个），但**跨模块的长链条**更醒目 ——

> `定积分换元` 失守 → `极坐标变换` → `柱面坐标` → `球面坐标`
>
> 一条链从第 5 章一直塌到第 10 章。学生会以为自己「重积分学不会」，
> 其实起点在第 5 章那个「换元时微元要跟着换」的动作上。
>
> 全树 16 个断层 → 收敛为 **8 个源头**，最大源头「二重积分化累次积分」（58 分）连带波及 4 个知识点。

**两门课的价值点不同**：数据结构适合展示「收敛」（13 个洞 → 4 个源头，一个 38 分的源头连带拖垮 8 个）；高等数学适合展示「跨模块迁移」（一个方法的缺失穿过三章造成连锁塌方）。

这条链的意义在于：学生以为自己在「第 4 章 树」出了问题，其实第 3 章的栈就没理解透。**跨章节的隐式依赖恰恰是卡顿高发区，也是本作品的价值所在。**

## 快速开始

需要 Node 18 及以上。

```bash
cd knowtree
npm install
npm run dev        # 开发模式，默认 http://localhost:5173
```

其他命令：

```bash
npm run typecheck  # TypeScript 严格模式检查
npm run build      # 类型检查 + 生产构建，产物在 dist/
npm run preview    # 预览构建产物，http://localhost:4173
```

构建产物是纯静态文件，`base: './'` 且无前端路由，**可直接部署到任意静态托管**（对象存储、静态网站托管、GitHub Pages 等），无需任何服务端配置。

### 领域层自检

知识图和归因算法不依赖 UI，可以脱离界面单独验证：

```bash
node scripts/verify-domain.ts     # 《数据结构》：归因引擎 + 知识树完整性
node scripts/verify-calculus.ts   # 《高等数学》：结构层 + 叙事层两组断言
```

它们带断言，退出码非零代表失败。**任何一次知识树依赖关系的改动之后都应该重跑** —— 依赖边写错不会报错，只会让归因链悄悄给出荒唐的结论。

两门课的验证脚本刻意分开：`verify-calculus.ts` 把断言分成 **结构层**（无环、无悬空依赖、字段完整）与 **叙事层**（演示画像能否撑起一条有说服力的归因链）。分开的理由是：结构错了是 bug，叙事不理想只是演示效果问题。混在一起会诱使人「为了让测试变绿去改数据」。

## 接入你自己的模型

应用默认运行在**演示模式**（内置样例回放，无需任何密钥，点开即可完整体验全部功能）。

要分析真实题目，进入「设置」页切换到**远程模型**，填入任意 OpenAI 兼容端点即可。已内置预设：

| 服务商 | Base URL | 默认模型 |
|---|---|---|
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4v-plus` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-vl-max` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 自建网关 | 自行填写 | — |

要求：模型需支持 **视觉输入**（用于读题）并以 **JSON 格式稳定输出**。

> **隐私说明**：API Key 只保存在你自己的浏览器 localStorage 中，不会上传到任何第三方服务器，也不写入任何日志文件。请求由浏览器直接发往你填写的端点。

## 几个值得说明的设计取舍

**知识树为什么画成 DAG 而不是树？**
课程知识结构天然是有向无环图 —— 一个知识点可以有多个前置。用严格的树形布局必然丢边，而丢掉的往往正是跨章节的关键依赖。因此树的可视化采用「章节分列 × 知识纵深」的自绘布局，每条依赖边如实画出。

**三级讲解为什么在数据结构上分开存？**
不是排版需要，是教学需要。如果「提示」和「完整答案」同屏出现，学生只会看答案。分开存，界面才能强制分级解锁。

**错因为什么被收敛到 4 类？**
自由文本的归因无法被验证，而且长得像废话。因此错因被强制归入：概念缺失 / 前置断层 / 方法误用 / 审题失误。

**每一条归因都必须挂上看得见的证据**
诊断报告里会展示：依据哪个知识点的定义、学生的哪一步错了、以及经过了哪条依赖路径。学生可以核对，而不是被迫相信。

## 两种交付形态

知树提供两种形态，**共用同一份知识树数据与同一套归因算法**：

| 形态 | 说明 |
|---|---|
| **网页版**（本仓库） | 完整功能：知识树 DAG 可视化、学情雷达图、错题本、教师端班级卡点热力图 |
| **LearnBuddy 专家**（智能体形态） | 可直接在对话框里诊断与追问，支持「这道题我卡在哪」这类自然语言提问 |

专家侧的归因引擎是网页版算法的 Python 等价实现（纯标准库，无第三方依赖），
读取由 `scripts/export-for-expert.ts` 导出的同一份 `knowledge-tree.json`。
**两版的归因结论经实测完全一致** —— 数据结构「函数调用栈 38 分，下游 9 个 / 已失效 8 个」、
高数「二重积分化累次积分 58 分，下游 4 个」，逐项吻合。

之所以不采用「换个模型把同一道题重讲一遍」的做法：归因结论必须是**确定性的、可复现的、
能向老师解释的**。模型负责读懂题和讲明白，算法负责判断卡在哪 —— 这个分工不能颠倒。

## 当前边界（如实说明）

这个项目采取的是「一门课做透，而不是四门课做半成品」的策略。以下是真实的未完成部分，不会被包装：

- **完整建模的课程有两门**：《数据结构》（38 个知识点，依赖关系已由授课教师人工校对）与《高等数学》（49 个知识点，9 章，覆盖上册全部主干与下册的多元微分、重积分、无穷级数，含跨模块隐式依赖）。知识树注册表里为线性代数、概率论保留了入口，标注为「规划中」。
- **尚未覆盖的数学模块**：《高等数学》未建模空间解析几何、曲线积分与曲面积分、傅里叶变换。
- **演示模式下只回放内置样例**（每门课一道真题，含学生手写痕迹）。这是为了保证任何人在无密钥环境下点开链接都能完整体验，代价是不能分析上传的真实照片。
- **教师端是演示数据**，尚未接入真实班级学情。
- **复测是自评制**（学生点「我做对了 / 没做对」），不是自动判分。
- **暂无移动端适配**，建议使用桌面浏览器体验。
- **无后端服务**，所有数据存在浏览器本地，换设备不同步。
